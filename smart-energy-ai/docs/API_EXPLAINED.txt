                    SMARTENERGY AI — APIS & KEYS EXPLAINED

Target Audience: Beginners needing to understand how APIs, keys, and environments work.

--------------------------------------------------------------------------------
1. CORE CONCEPTS EXPLAINED SIMPLY
--------------------------------------------------------------------------------

WHAT IS AN API?
API stands for "Application Programming Interface".
It is a formal set of rules that allows two computer programs to talk to each other.
- Analogy: When you sit in a restaurant, you don't enter the kitchen to cook the food.
  You speak to the waiter (the API), who carries your order to the kitchen (the server),
  and brings back your food (the data response).

WHAT IS AN LLM API?
An LLM API allows our Python application on your laptop to send a block of text
(the prompt) to a remote supercomputer running large models like LLaMA 3 or GPT-4,
and receive back an intelligent written response.

WHAT IS AN API KEY?
An API key is a unique, secret string of characters (like `gsk_abc123...`) that acts
as a digital password and username combined into one.
- Analogy: An electronic hotel keycard that allows access to your room.

WHAT IS A REQUEST AND RESPONSE?
- Request: The message your computer sends across the internet (e.g. "Here is the energy data; please summarize it").
- Response: The answer that the cloud server sends back across the internet (e.g. "Your energy consumption was highest at 8 PM").

WHAT IS AN ENVIRONMENT VARIABLE & A `.env` FILE?
- Environment Variable: A variable stored securely in your computer's operating system memory
  rather than typed into the source code files.
- `.env` file: A text file placed in your project root where you write:
  `GROQ_API_KEY=gsk_your_actual_key_here`
- `.env.example`: A template file that shows what variables are expected, without revealing
  your real secret password.

--------------------------------------------------------------------------------
2. WHERE EXACTLY IS THE API KEY USED IN THIS PROJECT?
--------------------------------------------------------------------------------
1. In `utils/config.py`:
   The line `load_dotenv(PROJECT_ROOT / ".env")` reads your `.env` file into Python.
   `config.llm.groq_api_key` extracts the key.

2. In `services/llm_service.py`:
   When `LLMService` initializes, it checks:
   `if self.groq_api_key and not self.groq_api_key.startswith("gsk_your_"):`
   If a valid key is found, it connects securely using the official `groq` or `openai` client.

3. In `agents/*.py`:
   Whenever an agent finishes its calculations, it calls `llm_service.generate_completion()`.
   The key is sent via HTTPS headers (`Authorization: Bearer <KEY>`) to the Groq/OpenAI cloud.

--------------------------------------------------------------------------------
3. WHY MUST THE API KEY NEVER BE HARD-CODED?
--------------------------------------------------------------------------------
1. GitHub Security Bots: Automated scrapers constantly crawl public repositories.
   If you push a hard-coded key to GitHub, it will be compromised within seconds.
2. Financial Risk: A stolen API key can rack up thousands of dollars in unauthorized usage.
3. Separation of Concerns: Code should remain identical across development, testing,
   and production. Only configuration files (`.env`) should change between environments.
4. Git Protection: Our `.gitignore` file explicitly lists `.env`, ensuring your secret key
   is never accidentally committed or uploaded.

--------------------------------------------------------------------------------
4. WHAT HAPPENS IF THE API IS UNAVAILABLE OR THE KEY IS MISSING?
--------------------------------------------------------------------------------
In many student projects, a missing API key causes the entire application to crash with
a nasty Python traceback.

In SmartEnergy AI, WE DESIGNED AN OFFLINE FALLBACK SYSTEM:
1. `services/llm_service.py` detects if the key is missing or invalid.
2. It logs: `[INFO] No valid LLM API key configured. Offline Fallback / Demo mode active.`
3. When agents request completions, `llm_service` smoothly bypasses the external network call
   and returns high-quality, pre-computed analytical summaries directly from Python.
4. Every numerical calculation (Forecasting, Anomaly Detection, Tariffs, Metrics) runs 100%
   locally on your machine and works perfectly without internet!
5. In the UI, a badge clearly displays:
   `ℹ️ [Demonstration / Fallback Mode: Offline Analytical Synthesis]`
   This demonstrates professional defensive programming to your college examiners!
